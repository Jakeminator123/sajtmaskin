OpenClaw Setup Guide — Sajtagenten (infra/openclaw)
============================================================

Purpose and architecture
------------------------
- OpenClaw runs as a standalone Render Docker Web Service. It is not part of
  the Vercel/Next.js deployment.
- The app proxies server-side requests from /api/openclaw/* and /api/did/chat
  to the gateway over HTTPS with a shared Bearer token.
- The public product remains Sajtagenten. Fast/balanced/strong are internal
  OpenClaw agent targets selected by server-owned routing.
- Dockerfile pins OpenClaw 2026.7.1-2. Upgrade the pin only in a dedicated PR
  with config tests and a Render smoke test; never use latest in production.


Repo paths
----------
- Docker root:       infra/openclaw/

Render service
--------------
Service type:  Web Service
Runtime:       Docker
Root dir:      infra/openclaw
Plan:          Standard (2 GB / 1 CPU)
Disk:          3 GB mounted at /root/.openclaw

Do not use Starter. The live service exceeded 2 GB and OOM-restarted on
2026-08-05. The persistent disk holds agent/session state and cannot be shrunk.

Secrets / instance values:
- OPENCLAW_GATEWAY_TOKEN=<secret shared with Vercel>
- OPENAI_API_KEY=<existing OpenAI platform key>
- SAJTAGENT_TARGET_SITE_URL=https://<site>
- SAJTAGENT_ALLOWED_ORIGINS=https://<app>,https://<optional-preview>
- JUICEFACTORY_API_KEY=<optional; only when that provider is used>

Committed safe defaults in render.yaml:
- OPENCLAW_GATEWAY_PORT=10000
- OPENCLAW_GATEWAY_BIND=lan
- OPENCLAW_HEARTBEAT_EVERY=0m
- OPENCLAW_MODEL_PRIMARY=openai/gpt-5.6-sol
- OPENCLAW_MODEL_FALLBACK=openai/gpt-5.6-terra,openai/gpt-5.5
- OPENCLAW_MODEL_BALANCED=openai/gpt-5.6-terra
- OPENCLAW_MODEL_BALANCED_FALLBACK=openai/gpt-5.6-sol,openai/gpt-5.5
- OPENCLAW_MODEL_FAST=openai/gpt-5.6-luna
- OPENCLAW_MODEL_FAST_FALLBACK=openai/gpt-5.6-terra,openai/gpt-5.5

The config generator validates URL/model envs, JSON-serializes all values and
writes /root/.openclaw/openclaw.json with mode 0600. Never build JSON via shell
interpolation. Heartbeat stays off until a real delivery channel exists.


Internal agents
---------------
- openclaw:sajtagenten          strong/default, Sol + high thinking
- openclaw:sajtagenten-balanced balanced, Terra + medium thinking
- openclaw:sajtagenten-fast     fast, Luna + low thinking

Each target has its own agent directory, explicit model/fallback chain, empty
skills list and tools.profile=minimal. OpenClaw bootstrap generation is off.
Session maintenance is enforced: pruneAfter 14d, maxEntries 500,
resetArchiveRetention 7d, maxDiskBytes 512mb and highWaterBytes 400mb.

OPENCLAW_REVIEW_REASONING_EFFORT is retired. The pinned gateway's OpenAI Chat
Completions endpoint does not pass reasoning_effort to the agent runtime;
per-agent thinkingDefault is the effective configuration.


Vercel app env
--------------
Required for the Sajtagenten surface:
- OPENCLAW_GATEWAY_URL=https://<gateway>.onrender.com
- OPENCLAW_GATEWAY_TOKEN=<same token as Render>
- IMPLEMENT_UNDERSCORE_CLAW=true

Routing rollout flag:
- OPENCLAW_MODEL_ROUTING_ENABLED=false/unset during the Render-first deploy
- OPENCLAW_MODEL_ROUTING_ENABLED=true after all three agents appear in the
  authenticated gateway /v1/models response

Set the flag for development, preview and production when those targets use
OpenClaw. OPENCLAW_GATEWAY_URL must never point to the app itself; that creates
a self-proxy loop. No D-ID Studio env changes are needed.


Rollout order
-------------
1. Merge/deploy Render with the model envs above.
2. Confirm GET <gateway>/health = 200 and authenticated GET <gateway>/v1/models
   lists openclaw/sajtagenten, openclaw/sajtagenten-balanced and
   openclaw/sajtagenten-fast.
3. Deploy Vercel while OPENCLAW_MODEL_ROUTING_ENABLED is false/unset.
4. Confirm GET <app>/api/openclaw/health has status=ok and readiness=ready.
5. Set OPENCLAW_MODEL_ROUTING_ENABLED=true on Vercel, redeploy, and confirm
   readiness=ready with all three requiredAgentIds.
6. Run one tips question, one normal Sajtagenten question, one review/debug
   question and one D-ID/avatar question. Logs show lane + agent, never model
   provider secrets.


Health semantics
----------------
- Render /health is liveness only.
- App /api/openclaw/health first checks liveness, then makes authenticated
  GET /v1/models and verifies every agent required by the routing flag.
- readiness=auth_failed means token mismatch/missing auth.
- readiness=missing_agents means Render has not deployed all required agents.
- Model quota/capacity is not probed: health must not spend paid model calls.


Device pairing and proxy warning
--------------------------------
The Control UI requires both the gateway token and one-time device approval:

  openclaw devices list --json
  openclaw devices approve <current-requestId>

Pending ids expire or are replaced by new connection attempts. Generate a
fresh request, list immediately and approve only the current id. The Render log
warning "Proxy headers detected from untrusted address" is expected because
Render terminates TLS. It is not a token or pairing failure. Do not trust
0.0.0.0/0 or broad proxy CIDRs to silence it.


Common failures
---------------
- reason=token_missing: paste the current token into Control UI and reconnect.
- auth_validated + pairing/1008: approve the current device request.
- readiness=auth_failed: Render and Vercel tokens differ, or one is missing.
- readiness=missing_agents: deploy Render first; leave routing flag off until
  all three agent ids exist.
- 405 from /v1/chat/completions: chatCompletions endpoint was not enabled.
- malformed origin/model at boot: paste only the env VALUE, never KEY=value.
- OOM/restart: inspect Render Events; do not trust host /proc memory numbers
  shown inside the container.
- stale OpenAI auth after key change: inspect each agent's persistent
  agent/codex-home/auth.json. Remove only a confirmed stale file, then restart;
  the running process keeps credentials in memory.

The app retries exactly one failure class during rolling deploys: HTTP 400
"Unknown agent" for fast/balanced is retried once against sajtagenten. Auth,
quota, network and generic upstream failures are not retried.


Security and incident handoff
-----------------------------
- Never commit or log keys/tokens.
- Device auth remains enabled.
- tools.profile=minimal and skills=[] prevent the public chat surface from
  receiving filesystem, shell, browser, messaging or subagent tools.
- Client-supplied system roles are rejected. Tips file context is rebuilt only
  after tenant ownership is verified. D-ID sends bounded explicit history and
  does not also create a client-controlled persistent OpenClaw session.
- The token visible in the incident screenshot must be treated as exposed.
  After merge: generate a new OPENCLAW_GATEWAY_TOKEN, set the identical new
  value in Render and Vercel, restart/redeploy both, then paste the new token in
  Control UI and reconnect. The repository cannot rotate live secrets safely.
