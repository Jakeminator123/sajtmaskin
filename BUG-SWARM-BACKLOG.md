# Bug-backlog

**Enda aktiva bugglistan i repot.** Lokal Markdown är källan till sanning — ingen extern tracker. Formatkontrollen (`npm run check:bug-backlog`) validerar köerna. Canvas-generatorn läser endast **Aktiva produktionsbuggar** och **Release blockers bakom feature flag**.

Den fulla omtriageringen, inklusive mappningen från samtliga 114 tidigare aktiva, repro- och policyrader, finns i [`docs/operating/bug-backlog-review-2026-08-05.md`](docs/operating/bug-backlog-review-2026-08-05.md). Avslutade eller avfärdade rader flyttas till senaste filen under [`docs/plans/avklarat/bug-swarm/`](docs/plans/avklarat/bug-swarm/).

## Regler

| Regel                         | Kontrakt                                                                                                         |
| ----------------------------- | ---------------------------------------------------------------------------------------------------------------- |
| En rad, en premiss            | Varje aktiv rad ska beskriva ett enda falsifierbart fel. Delvis lösta moder-rader delas.                         |
| Stabilt ID                    | `SW-###` behålls när en rad flyttar mellan köer. Delar använder suffix, exempelvis `SW-040B`.                    |
| Aktiv betyder bekräftad       | Hypoteser ligger i repro-kön. Policyfrågor och medvetna beteenden ligger i beslutskön.                           |
| Feature flag är egen räckvidd | Fel bakom avstängd flagga är releaseblockers, inte pågående produktionsincidenter.                               |
| Fix flyttas                   | En löst rad tas bort från den operativa kön och läggs i arkivet med commit- eller PR-referens.                   |
| Kort kö, lång evidens         | Aktiv rad innehåller fel, kodbevis och nästa steg. Historik och längre resonemang ligger i granskningsjournalen. |
