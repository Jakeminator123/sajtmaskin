OpenClaw Setup Guide — Sajtagenten (infra/openclaw)
============================================================

Purpose and architecture
------------------------
- OpenClaw runs as a standalone Render Docker Web Service. It is not part of
  the Vercel/Next.js deployment.
- The app proxies server-side requests from /api/openclaw/* and /api/did/chat
  to the gateway over HTTPS with a shared Bearer token.
- The public product remains Sajtagenten. Fast/balanced/strong are internal
  OpenClaw agent targets selected by server-owned routing.
- Dockerfile pins OpenClaw 2026.10.34 and Node 24.22.1. The OpenClaw release
  adds GPT-6.2 Astra and Sol support on the OpenAI Responses route.
  https://github.com/openclaw/openclaw/releases/tag/v2026.10.34

Render service
--------------
Service type:  Web Service
Runtime:       Docker
Root dir:      infra/openclaw
Plan:          Standard (2 GB / 1 CPU)
Disk:          3 GB mounted at /root/.openclaw

Create the service from the Blueprint at infra/openclaw/render.yaml on master.
The service keeps auto-deploy enabled, but its build filter only includes
infra/openclaw/** and ignores this guide and .gitignore. Normal
app/docs merges therefore do not rebuild or restart the gateway. Manual
deploys and Blueprint configuration syncs are intentionally unaffected.

Do not use Starter. The live service exceeded 2 GB and OOM-restarted on
2026-08-05. The persistent disk holds agent/session state and cannot be shrunk.

Workspace webhook `openclaw-sajtagenten-events` (Integrations → Webhooks)
notifies on deploy/build/server/disk events only — not container logs.
Destination and signing secret are operator-local; do not commit them or
point the URL at this gateway's /hooks. See
docs/runbooks/openclaw-gateway.md (Workspace-webhook).

Secrets / instance values:
- OPENCLAW_GATEWAY_TOKEN=<secret shared with Vercel>
- OPENAI_API_KEY=<existing OpenAI platform key>
- SAJTAGENT_TARGET_SITE_URL=https://<site>
- SAJTAGENT_ALLOWED_ORIGINS=https://<app>,https://<optional-preview>

Committed safe defaults in render.yaml:
- OPENCLAW_GATEWAY_PORT=10000
- OPENCLAW_GATEWAY_BIND=lan
- OPENCLAW_HEARTBEAT_EVERY=0m
- OPENCLAW_MODEL_PRIMARY=openai/gpt-6.2-astra
- OPENCLAW_MODEL_FALLBACK=openai/gpt-6.2-sol,openai/gpt-5.6-sol,openai/gpt-5.5
- OPENCLAW_MODEL_BALANCED=openai/gpt-6.2-sol
- OPENCLAW_MODEL_BALANCED_FALLBACK=openai/gpt-5.6-sol,openai/gpt-5.5
- OPENCLAW_MODEL_FAST=openai/gpt-6.2-sol
- OPENCLAW_MODEL_FAST_FALLBACK=openai/gpt-5.6-terra,openai/gpt-5.5

The config generator validates URL/model envs, JSON-serializes all values and
writes /root/.openclaw/openclaw.json with mode 0600. Never build JSON via shell
interpolation. Heartbeat stays off until a real delivery channel exists.
Nonempty Render Environment values override the generator defaults. A Blueprint
sync can apply the YAML values to a connected service. Paste only each value,
without quotes or the key prefix. Keep the existing OPENAI_API_KEY and gateway
token in their current environment variables.


Internal agents
---------------
- openclaw:sajtagenten          strong, GPT-6.2 Astra + high thinking
- openclaw:sajtagenten-balanced balanced, GPT-6.2 Sol + medium thinking
- openclaw:sajtagenten-fast     fast, GPT-6.2 Sol + low thinking

Each target has its own agent directory, explicit model/fallback chain, empty
skills list and the same explicit tool policy as the gateway. OpenClaw bootstrap generation is off.
The fast primary is also the utility model with low thinking. OpenAI entries
use the built-in OpenClaw runtime. The keyed agent roster preserves the old
agent IDs and paths, with sajtagenten as system-agent and heartbeat owner.
Session maintenance is enforced: pruneAfter 14d, maxEntries 500,
resetArchiveRetention 7d, maxDiskBytes 512mb and highWaterBytes 400mb.

OPENCLAW_REVIEW_REASONING_EFFORT is retired. The pinned gateway's OpenAI Chat
Completions endpoint does not pass reasoning_effort to the agent runtime;
per-agent thinkingDefault is the effective configuration.


Vercel app env
--------------
Required for the Sajtagenten surface:
- OPENCLAW_GATEWAY_URL=https://openclaw-sajtagenten.onrender.com
  (old sajtagenten.onrender.com is suspended; do not point here)
- OPENCLAW_GATEWAY_TOKEN=<same token as Render>
- IMPLEMENT_UNDERSCORE_CLAW=true

Routing rollout flag:
- OPENCLAW_MODEL_ROUTING_ENABLED=false/unset during the Render-first deploy
- OPENCLAW_MODEL_ROUTING_ENABLED=true after all three agents appear in the
  authenticated gateway /v1/models response

Set the flag for development, preview and production when those targets use
OpenClaw. OPENCLAW_GATEWAY_URL must never point to the app itself; that creates
a self-proxy loop. No D-ID Studio env changes are needed.


Rollout order from 2026.7.1-2
----------------------------
1. Before promotion to master, record the live Render deploy ID and the six
   effective model values. Check project access to GPT-6.2 Astra and Sol with
   the existing Render OpenAI key using GET /v1/models/<model-id>. Confirm the
   fallback models are available to that project too.
2. Schedule the deploy window and verify a recoverable pre-upgrade backup of
   /root/.openclaw. The disk holds SQLite and other agent state. Keep a
   consistent backup with the gateway stopped or use its supported backup
   procedure. Render disk snapshots are daily, retained seven days, and
   restore the whole disk. Keep the backup private and rehearse migration on
   an isolated compatible copy before mounting the live disk on the new build.
   If OpenClaw reports retired formats requiring an intermediate release, use
   the documented 2026.9.5 bridge on the copy and follow its Doctor instructions.
   https://render.com/docs/disks#disk-snapshots
   https://github.com/openclaw/openclaw/blob/v2026.10.34/docs/install/updating.md#upgrading-very-old-versions
3. In Render → openclaw-sajtagenten → Environment update the six values above
   and choose Save only shortly before the reviewed upgrade deploy. Coordinate
   with master promotion or disable auto-deploy during the window, because the
   next deploy consumes these values. Promote the new Dockerfile and deploy
   that commit. Save and deploy would reuse the existing build.
   https://render.com/docs/configure-environment-variables
4. Wait for the upgraded deploy to go live. Check the version and primaries in
   boot logs, GET <gateway>/health and /startupz = 200, and authenticated GET /v1/models
   listing openclaw/sajtagenten, openclaw/sajtagenten-balanced and
   openclaw/sajtagenten-fast. Confirm GET <app>/api/openclaw/health has
   readiness=ready and all three requiredAgentIds when routing is enabled.
5. Verify one tips question, one normal Sajtagenten question, one review/debug
   question and one D-ID/avatar question in the approved smoke test. Confirm
   actual provider model and auth route as well as the agent ID. If agent auth
   requires a saved OpenAI API-key profile, reuse the existing key via protected
   stdin with openclaw models auth paste-api-key --provider openai and verify
   the profile selected by each agent. Keep device approval and minimal tools.
   https://github.com/openclaw/openclaw/blob/v2026.10.34/docs/cli/models.md#auth-profiles

For a model-only rollback, restore the previous six env values and redeploy
the verified compatible build. A Dashboard deploy rollback uses that deploy's
saved env values for the rollback instance. Restore the saved service env
values separately for future standard deploys. The persistent disk is shared
across deploys. If the schema was migrated, restore a compatible backup while
the gateway is stopped before starting the older version. This recovery can
discard newer session data and requires the operator's approval.
https://render.com/docs/rollbacks#whats-rolled-back


Health semantics
----------------
- Render /health is liveness only.
- App /api/openclaw/health first checks liveness, then makes authenticated
  GET /v1/models and verifies every agent required by the routing flag.
- readiness=auth_failed means token mismatch/missing auth.
- readiness=missing_agents means Render has not deployed all required agents.
- Model quota/capacity is not probed: health must not spend paid model calls.


Device pairing and proxy warning
--------------------------------
Login recipe (Swedish, step by step):
docs/runbooks/openclaw-gateway.md#dashboard-inloggning

The Control UI requires the gateway token plus one-time device approval.
Password field is unused. Approve requestId, never deviceId:

  openclaw devices list --json
  openclaw devices approve <current-requestId>

Pending ids expire or are replaced by new connection attempts. Generate a
fresh request, list immediately and approve only the current id. The Render log
warning "Proxy headers detected from untrusted address" is expected because
Render terminates TLS. It is not a token or pairing failure. Do not trust
0.0.0.0/0 or broad proxy CIDRs to silence it.


Common failures
---------------
- reason=token_missing: paste the current token into Control UI and reconnect.
- auth_validated + pairing/1008: approve the current device request.
- readiness=auth_failed: Render and Vercel tokens differ, or one is missing.
- readiness=missing_agents: deploy Render first; leave routing flag off until
  all three agent ids exist.
- 405 from /v1/chat/completions: chatCompletions endpoint was not enabled.
- malformed origin/model at boot: paste only the env VALUE, never KEY=value.
- OOM/restart: inspect Render Events; do not trust host /proc memory numbers
  shown inside the container.
- stale OpenAI auth after key change: inspect each agent's persistent
  agent/codex-home/auth.json. Remove only a confirmed stale file, then restart;
  the running process keeps credentials in memory.

The app retries exactly one failure class during rolling deploys: HTTP 400
"Unknown agent" for fast/balanced is retried once against sajtagenten. Auth,
quota, network and generic upstream failures are not retried.
Provider model fallbacks share the OpenAI credential route. An invalid OpenAI
key can fail the entire chain. Check provider access and gateway token auth
separately when investigating a 401.


Security and incident handoff
-----------------------------
- Never commit or log keys/tokens.
- Device auth remains enabled.
- The global and per-agent policies allow session_status and deny gateway and
  presence. The explicit allowlist preserves the pre-upgrade tool set even if
  upstream adds tools to its minimal profile. Builder actions are app-owned.
- Client-supplied system roles are rejected. Tips file context is rebuilt only
  after tenant ownership is verified. D-ID sends bounded explicit history and
  does not also create a client-controlled persistent OpenClaw session.
- The token visible in the incident screenshot must be treated as exposed.
  After merge: generate a new OPENCLAW_GATEWAY_TOKEN, set the identical new
  value in Render and Vercel, restart/redeploy both, then paste the new token in
  Control UI and reconnect. The repository cannot rotate live secrets safely.
